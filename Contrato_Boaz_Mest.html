ANEXO I – ESPECIFICAÇÕES TÉCNICAS DO SISTEMA

As características técnicas aplicadas ao desenvolvimento e funcionamento do "Sistema Mest SoluTIon" englobam as seguintes tecnologias e diretrizes de infraestrutura:

1. Estrutura de Indentação e Padrões de Código
O código-fonte obedece a padrões rígidos de formatação estabelecidos pela comunidade de desenvolvimento (PEP-8 para Python e Prettier para Javascript/HTML), garantindo alta legibilidade e manutenibilidade técnica. O sistema é mantido através de controle de versão (Git) com histórico de alterações em repositório privado no GitHub.

2. Hospedagem e Requisitos Mínimos de Servidor
O sistema encontra-se hospedado integralmente em ambiente de computação em nuvem (Cloud Computing) de alta disponibilidade, provido pela PythonAnywhere (servidores na infraestrutura da AWS - Amazon Web Services).

  • Requisito do Servidor (Atual): Configuração em conta tipo Hacker ou superior (US$ 15,50/mês), fornecendo processos persistentes (Web Workers) para suporte do tráfego web simultâneo e execução de tarefas de segundo plano (CRON Jobs).
  • Escalabilidade: A arquitetura do sistema é stateless (sem estado guardado na memória da aplicação), o que significa que o sistema é pronto para escalabilidade horizontal, podendo receber balanceadores de carga (Load Balancers) e expansão de recursos conforme o crescimento de usuários.

3. Linguagem de Programação (Backend)
Toda a lógica de negócios, integrações, regras matemáticas da calculadora e comunicação é desenvolvida em Python (versão 3.10 ou superior), utilizando o ecossistema robusto e seguro do framework corporativo Django (versão 4.2+).

4. Estrutura de Banco de Dados
O armazenamento persistente das informações é operado por banco de dados relacional (SQL). No ambiente atual, o sistema já encontra-se operando com banco de dados de alta performance MySQL. A camada de modelo de dados (ORM - Object-Relational Mapping) provê segurança e garante total portabilidade da base estrutural. O modelo inclui estratégias de indexação (indexes) nas colunas de busca para mitigar lentidão em consultas (queries).

5. Estrutura do Front-end (Interface do Usuário)
A interface interativa apresentada aos usuários (telas e formulários) é construída sob a arquitetura clássica MVT (Model-View-Template) com HTML5 semântico, CSS3 nativo (arquivo base.css centralizado com design system), e Javascript puro (Vanilla JS) / jQuery para validações em tempo real na tela, formatações de máscaras, e execução da calculadora de orçamentos de forma fluída no navegador do cliente (sem necessidade constante de atualização de página).

6. APIs de Comunicação e Integração
O sistema não funciona de maneira isolada. Ele se comunica ativamente com serviços terceiros por meio de integrações avançadas:

  • API Asaas (Pagamentos): Integração RESTful que gera boletos, cobranças PIX, links de pagamento e realiza o acompanhamento automatizado do status financeiro (webhooks de pagamento aprovado/vencido).
  • Brasil API (Dados Cadastrais): Consumo de endpoint JSON para resolver dados de CNPJ, consultando automaticamente a Razão Social e os CNAEs primários e secundários em tempo real na tela da calculadora.
  • Automação ESO (RPA via BeautifulSoup/Requests): Um bot integrado ao servidor realiza acesso autenticado (session management via requests), processamento de HTML em memória (web scraping) e mineração de dados na base de saúde ocupacional da plataforma ESO, extraindo contagem de vidas e atestados para cruzamento de dados com a cota do contrato, injetando o resultado diretamente na base da MEST.

7. Código-Fonte e Propriedade
Conforme Cláusula Sexta do Contrato Principal, o repositório de código-fonte completo é de propriedade da CONTRATADA. A CONTRATANTE detém a licença de uso do software final compilado, juntamente com a integralidade dos dados inseridos no banco de dados.

8. Mapa do Sistema (Estrutura de Módulos)
A arquitetura de diretórios e divisão de responsabilidades do sistema baseia-se nos seguintes aplicativos modulares e independentes:

  • accounts: Gestão de usuários, logins, senhas e perfis de permissão.
  • empresas: Cadastro de clientes, contatos, filiais e histórico.
  • orcamentos: Formulários da calculadora, regras de precificação comercial (Risco NR4), geração de contratos digitais e PDFs dinâmicos.
  • finances: Motor financeiro local integrado às faturas e parcelamentos do Asaas.
  • eso_integration & sync_app: O "cérebro" autônomo que varre a base da ESO para confrontar limites de contrato.
  • dashboard_app: Centro de visualização de métricas gerenciais.

9. Monitoramento em Tempo Real e Rastreamento de Erros
O sistema possui integração ativa com a plataforma Sentry, uma ferramenta de monitoramento contínuo de performance e rastreamento de erros em tempo real. Em caso de falhas sistêmicas, telas de erro, travamentos ou gargalos de desempenho, o Sentry captura a exceção imediatamente e emite alertas automáticos por e-mail para a equipe técnica da CONTRATADA. Isso garante um suporte proativo, permitindo que a correção seja iniciada muitas vezes antes mesmo de a CONTRATANTE notar o problema.

10. Escalabilidade, Concorrência e Performance
Para garantir a estabilidade diante das dúvidas técnicas levantadas, a arquitetura obedece aos seguintes pilares:

  • Concorrência e Escalabilidade: O servidor PythonAnywhere gerencia múltiplos Web Workers, permitindo o atendimento simultâneo de requisições. O sistema é apto tanto para escalabilidade vertical (aumento de RAM/CPU no plano) quanto horizontal. Além disso, o banco de dados MySQL gerencia o travamento de registros (row-level locking) para evitar conflitos quando múltiplos clientes geram orçamentos ao mesmo tempo.
  • Tempo de Resposta e Cache: O framework Django é otimizado para respostas rápidas (milissegundos) em operações críticas. O sistema já está preparado para receber camadas de cache em memória (como Redis ou Memcached) para aliviar consultas pesadas no banco de dados, caso a demanda exija no futuro.
  • Testes e Capacidade: O ambiente atual comporta de forma fluida a operação diária da clínica. Testes de carga ou de stress de alto volume poderão ser provisionados no futuro sob demanda, visando simular milhares de acessos caso a base de usuários da CONTRATANTE cresça exponencialmente.
